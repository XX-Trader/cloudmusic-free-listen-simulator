# 官方免费听流程接口地图（手机端只读观测）

本文记录通过 ADB 被动观测网易云手机客户端自身日志得到的接口调用序列，用于说明“官方免费听流程具体怎么走”。

观测方式：清空 `logcat` 后让客户端自己请求，读取 `cr_request` 标签中的请求 URL。观测过程只读取客户端已发出的请求，不构造、不重放、不篡改任何请求。

## 1. 入口与任务

| 接口 | 作用 |
| --- | --- |

| `/eapi/ad/homepage/free/tab/extend` | 免费听页扩展信息 |
| `/eapi/ad/homepage/free/tab/jigsaw?method=GET` | 拼图任务（每日可完成 2 次） |
| `/eapi/ad/homepage/free/tab/module/v2?origin=2007` | 免费听页模块编排 |
| `/eapi/ad/homepage/free/tab/nonstop?method=POST&adExtJson={...}` | 不间断拉流，携带完整设备指纹 |
| `/eapi/ad/homepage/free/tab/pullnew/retention?method=GET&data={"entranceType":"FREE_LISTEN"}` | 留存与任务状态 |
| `/eapi/ad/listening/free/tab/homepage/stage/info?method=GET&data={"entranceType":"FREE_LISTEN"}` | 免费听阶段信息 |

## 4. 请求形态与约束

从 `adExtJson` 参数可以直接看到客户端上报的设备信息：

- `android_id`、`oaid`、`adDeviceId`、`bootMark`、`updateMark`
- `manufacturer`、`mobilename`、分辨率、网络类型
- 公网 `ipv4` / `ipv6`、经纬度 `lbs`
- 完整 `useragent`

同时可以看到：

1. 接口基址是 `https://interface3.music.163.com/eapi/...`，**参数体是加密的**（`data=`、`adExtJson=` 均为密文载荷），不是明文 JSON。
2. 请求与设备标识、启动标记、网络出口绑定，并存在专门的 `/eapi/ad/sniffing` 反自动化检测。

## 5. 奖励发放链路（实测时序）

2026-10-26 11:38 的一次完整成功任务，客户端自身的请求顺序如下（时间取自 logcat）：

| 时间 | 接口 | 含义 |
| --- | --- | --- |
| 11:38:47.9 | `/eapi/ad/monitor/impress` | 广告曝光 |
| 11:38:48.044 | `/eapi/ad/monitor/incentive/video` | 激励视频停留上报（8 秒到点） |
| 11:38:48.117 | `/eapi/ad/loading/current` | 当前广告加载状态 |
| 11:38:48.118 | `/eapi/ad/prefetch/select` | 预取下一个广告 |
| **11:38:48.367** | **`/eapi/ad/listening/rights/gain`** | **领取权益：发放 30 分钟** |
| 11:38:50.558 | `/eapi/song/enhance/privilege` | 歌曲播放权限校验 |
| 11:39:22.592 | `/eapi/ad/homepage/free/tab/asset` | 回写剩余时长 |

要点：

1. **奖励发放接口是 `/eapi/ad/listening/rights/gain`**，客户端在激励视频监控上报之后调用它。
2. 权益不是客户端本地记账，而是服务端在收到监控上报后写入；随后 `free/tab/asset` 回读到的剩余时长即为权威值。
3. 播放侧走 `/eapi/song/enhance/privilege` 与 `/eapi/song/enhance/player/url`；本项目的 `vip_probe.py` 只读复用了播放授权这一端。
4. 这条链路与 `rights/gain` 之前的 `ad/monitor/*` 是一体的：只发权益请求而不发监控上报，客户端没有可上报的观看事实。

## 6. 接口链路提取工具

`api_trace.py` 解析客户端自己的 logcat，输出结构化调用链与奖励接口命中情况：

```pwsh
pwsh -NoProfile -Command "python -B ./api_trace.py --log <logcat文件>"
pwsh -NoProfile -Command "python -B ./api_trace.py --wait 5"
```

输出包含请求总数、按类目统计、`reward_gain_seen` 与命中时间戳。工具只读取已经发出的请求。

## 7. 结论

- 官方免费听流程的“具体方法”是：客户端在 `interface3.music.163.com/eapi` 下用加密参数拉取任务 → 上报广告开始与曝光 → 广告落地页停留满 8 秒 → 上报激励视频监控 → 调用 `rights/gain` 领取权益 → `free/tab/asset` 回写剩余时长。
- 权益到账后，播放侧读取播放授权并按额度放行；本项目 `vip_probe.py` 只读复用了其中的**权益查询与播放授权**两端。
- 广告点击与停留属于真实广告互动，由客户端在人工或界面自动化操作下完成；项目不构造、不重放这些请求。

## 8. 与本项目实现的对应关系

| 官方接口 | 本项目对应物 | 性质 |
| --- | --- | --- |
| `free/tab/asset` | `account_gate.py` / `vip_probe.py` 的权益查询 | 只读复用 |
| `song/enhance/player/url` | `vip_probe.py` 的播放授权读取 | 只读复用 |
| `ad/get`、`ad/flow/get` | 离线模拟器的任务签发 | 纯本地等价物 |
| `ad/start/info/upload`、`ad/monitor/*` | 离线模拟器的审计轨迹 | 纯本地等价物 |
| 落地页点击与 8 秒停留 | 离线模拟器的虚拟停留；真机上由 `device_automation.py` 驱动官方界面完成 | 真实广告互动发生在官方客户端内 |
| `ad/listening/rights/gain` | 不复现 | 奖励发放由官方客户端在监控上报后发起，项目不调用 |
