# VIP 播放验证实施规划

## 1. 当前阶段

P3：只读播放验证已完成实现与单元测试，真实绿灯结论待一次新的官方任务权益。

## 2. 变更影响分析

### 新增文件

- `vip_probe.py`
- `tests/test_vip_probe.py`
- `docs/网易云/VIP播放验证/` 三件套

### 修改文件

- `account_gate.py`：`read_gate` 与 `wait_for_rights` 增加可选请求器注入；`GateResult` 增加 `account_id` 字段并新增 `to_public_dict`，保证 CLI 输出仍不含账号原值。

### 直接影响

- 账号门禁的调用方式向后兼容，默认行为不变。
- 新增一个只读 CLI 入口。

### 配置与兼容性

- 不新增环境变量与第三方依赖。
- `account_gate.py` 输出字段集合保持不变。

## 3. 分步实施

### 步骤 1：接口只读探测

1. 用当前桌面会话探测候选与播放接口。
2. 记录可用路径与被服务端拒绝的路径。
3. 确认 `fee` 判定 VIP、`freeTimeTrialPrivilege` 与 `cannotListenReason` 判定放行。

验证点：探测脚本只读、结果落在 `artifacts/`、不写入仓库正文。

### 步骤 2：门禁注入改造

1. `read_gate` 增加可选 `requester`。
2. `GateResult` 增加 `account_id`，输出改用 `to_public_dict`。

验证点：既有 3 项门禁测试继续通过。

### 步骤 3：探针实现

1. `ProbeSession` 负责计数与重试。
2. 歌单 → 曲目 → 详情 → VIP 候选。
3. 播放授权判定与有界取流。

验证点：核心函数不超过 50 行；无凭证输出。

### 步骤 4：测试

1. 门禁关闭时短路且请求数为 2。
2. 自动候选选中首个 `fee == 1` 曲目。
3. 阻断原因存在时判定 `blocked` 且不取流。
4. 指定歌曲跳过歌单查询。
5. 输出不含凭证与账号原值。

验证点：全部走假服务，不触网。

### 步骤 5：实机验证

1. 权益为 0 时实跑，确认 `gate_closed` 与退出码 2。
2. 取得新权益后实跑，确认 `entitled` 与退出码 0。

## 4. 防重构破坏策略

- `account_gate` 默认调用路径不变，旧调用方无需修改。
- 探针不修改 `simulator.py`，两者运行域保持隔离。
- 接口路径以实测可用集合为准，不引入未验证路径。

## 5. 完成定义

- 单元测试通过且不触网。
- 门禁关闭路径实机验证通过。
- 真实权益下取得一次 `entitled` 绿灯后，本阶段收口。
