# 免费听离线模拟实施规划

## 1. 当前阶段

当前执行 P1：在既有纯内存状态机上增加 CLI 全自动执行器和结构化审计轨迹。

## 2. 变更影响分析

### 修改文件

- `simulator.py`
- `tests/test_simulator.py`
- `run.ps1`
- `README.md`
- `todo.md`
- `done.md`

### 直接影响

- `simulate()` 的内部编排和 JSON 输出字段。
- CLI 场景来源与 PowerShell 参数白名单。
- 既有 8 项离线测试及新增自动执行器测试。

### 间接影响

- README 中的示例输出和场景说明。
- 后续 VIP 播放验证只能消费真实只读门禁结果，不得消费演示余额。

### 配置与兼容性

- 不新增环境变量、第三方依赖、数据库或文件持久化。
- 保留既有四个场景名和关键输出字段。
- 新增字段仅描述离线自动流程和审计轨迹。

## 3. 分步实施

### 步骤 1：测试先行

1. 新增成功场景审计顺序断言。
2. 断言点击、停留和领取均由自动执行器完成。
3. 断言停留不足与服务拒绝不增加余额。
4. 断言重复领取审计为幂等，且余额只增加一次。
5. 断言每个场景的 `network_requests` 为 0、`real_entitlement_granted` 为 `false`。
6. 新增 PowerShell 场景集合与 Python 注册表一致性测试。

验证点：新增测试在实现前应暴露缺失字段或缺失类型，而不是因测试语法错误失败。

### 步骤 2：核心模型

1. 新增 `ScenarioSpec` 和 `AuditEvent` 不可变数据类。
2. 新增 `AD_STARTED` 与 `DWELLING` 状态。
3. 为 `Flow` 增加合法的开始广告和进入停留方法。
4. 用 `SCENARIOS` 注册表承载四个场景配置。

验证点：底层既有边界测试继续通过。

### 步骤 3：自动执行器

1. 新增 `AutoRunner`，依次签发任务、开始广告、点击、推进虚拟时间和自动领取。
2. 记录每个动作的顺序号、虚拟时间、结果和原因。
3. 重复领取场景追加幂等审计事件。
4. `simulate()` 仅负责按名称取场景并调用执行器。

验证点：核心函数不超过 50 行；不存在三分支以上的场景判断链。

### 步骤 4：CLI 与文档

1. CLI `choices` 从 `SCENARIOS` 生成。
2. PowerShell 保持同名白名单，由测试阻止集合漂移。
3. 更新 README 的流程、示例和输出字段。

验证点：四个场景均可通过 `run.ps1` 执行并输出合法 JSON。

### 步骤 5：回归与收尾

1. 运行 `python -B -m unittest discover -s tests -v`。
2. 分别运行 `success`、`short-stay`、`server-rejected`、`duplicate`。
3. 搜索网络导入和真实凭证字段，确认离线核心未引入。
4. 更新 `todo.md`、`done.md` 和文档验收状态。
5. 执行 `graphify update .` 增量更新知识图谱；若命令未安装，保留完整错误并报告。

## 4. 防重构破坏策略

- 保留 `DemoServer`、`Flow`、`simulate()` 和四个场景名，避免无关调用面变化。
- 先固定现有行为测试，再重构场景分派。
- 新旧关键结果字段并存：`mode`、`scenario`、`state`、`events`、`receipt`、`demo_balance_minutes`。
- 不触碰 `account_gate.py` 的真实账号只读逻辑。
- 不在本阶段引入 VIP 播放、桌面启动或真实广告接口。

## 5. 完成定义

- 功能三件套与全局任务文档已同步。
- 全量测试通过。
- 四个 CLI 场景输出可解析 JSON。
- 成功场景具有完整自动轨迹；失败场景没有演示余额误增。
- 输出可直接证明：纯离线、虚拟时间、演示回执、零真实权益。
